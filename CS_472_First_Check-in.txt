CS 472 First Check-in
Ali Eser


The biggest hurdle so far has been figuring out how to translate the “casual” math of fair allocation into rigid Rocq types. I spent hours and hours trying to design the most versatile framework for temporal instances and allocations. I went through at least five different architectural iterations. Initially, I just used definition aliases to make the code read like some papers' notation. I soon realized that gave me no actual logical structure or proof obligations. I then tried using Records with partition properties built right into them. This seemed great until I hit a wall with temporal fairness later on. I originally wanted my cumulative allocations to return an actual allocation Record. I quickly realized that proving the intersection of an existing allocation with daily item arrivals is both disjoint and complete is a massive puzzle on its own. Doing all that proof work just to state the baseline definition of fairness felt completely backwards. I ended up stripping the architecture down. I defined fairness directly on raw functions that map agents to bundles instead. Honestly, I still feel like I failed at making the elegant modular architecture I originally envisioned. At least the definitions finally compile and accurately represent the framework.


Beyond the architecture struggles, I ran into the learning curve of integrating the stdpp library and various new Rocq features into my project. I had to piece together how finite types, sets, and fold operations actually interact for my specific use case. Translating a trivial sequence of unions turned into a frustrating wrestling match with type conversions between lists and finite sets. The same applied to using Context inside Sections to properly manage implicit variables, or figuring out how to inject proof requirements into Record definitions.
